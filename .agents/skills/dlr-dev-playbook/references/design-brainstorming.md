# 新功能设计

先读现有实现、测试及 `AGENTS.md`「流程编排技能的使用边界」。目标是解决影响实现的产品选择，不是完成固定仪式。

- 明确用户要达到的结果、现有接口和会受影响的调用方；只有答案会改变方案时才提问。
- 需求尚不明确的新功能，给出简短方案：行为、影响范围、错误处理、验证方式；存在实质取舍时说明替代方案。
- 必要的设计确认合并为一次；已有明确要求或批准方案直接执行。修复、重构、配置、文档改动不重复审批。
- 跨模块或长期架构决定值得落盘时使用仓库现有文档位置；简单任务留在对话即可，不强制新建规格、提交文件或调用其他技能。
- mockup、独立评审按实际收益选用，不自动启动浏览器服务或子代理。需要规格复核时可参考 [评审要点](../assets/spec-reviewer-prompt.md)。
