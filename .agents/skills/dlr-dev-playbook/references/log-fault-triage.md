# 日志分诊

先读 `AGENTS.md` 的脱敏约束及对应主题，不把回退 WARNING 自动当成需要修的缺陷。

1. 从时间、级别、模块/函数定位实际发出点；日志行号可能已漂移，用消息与符号核对。
2. 连同后续结果判断：回退后成功通常是正常容错；持续失败、空异常原因、漏传代理或凭据、重复昂贵请求才需要继续查。
3. 复现最小失败分支，沿当前实现修根因；保留持续失败时的降级，不从旧配方复制探针或请求逻辑。
4. 跑相关行为测试；涉及拉流时按完成定义记录真机验证或未验证范围。

## 常见入口

- 空异常信息：仅加 `{e}` 无法得到异常类型；在现有 i18n 常量模板中传 `type(e).__name__` 和经 mask_credentials 处理的异常文本。需要栈时遵循现有日志机制，避免把带凭据的异常原文泄露。
- HEAD 拒绝可用流：复用 stream_select 的限量 GET、复核和末位回退；不要写遇 text/html 就提前返回的新探针，也不要用 endswith 判断带查询参数的流地址。
- 抖音 200 空体 / status_code 软拒绝：核对 UA、Cookie 和当前重试链；显式离线 room_status 与缺数据不同，不把离线轮改回 HTML 抓取。
- 关闭卡住、段错误：保留退出码/线程与主线程信息再定位；不能仅因本机曾有环境问题就忽略新崩溃。

只报告脱敏日志、实际检查和剩余不确定项，不固定要求逐行表格或全量测试。
